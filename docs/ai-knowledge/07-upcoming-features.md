# Upcoming features (NOT available yet)

Nothing in this file is live. The AI must never describe these as available, demo-able, priced or dated.

## The list

| Feature | What it will be (internal description) |
| --- | --- |
| Prototype testing | Test design prototypes with recruited participants |
| Website usability testing | Watch how users complete tasks on a live website |
| Screen and audio recording | Record participant sessions for usability studies |
| Qualitative research | Interviews and other qualitative methods alongside surveys |
| Lumor Insights (research repository) | An organisation-wide repository of results with AI synthesis across studies |
| SMB QR feedback plan | A low-cost plan for retail, cafés, clinics and similar businesses collecting feedback by QR code. The QR collector itself is live; only this plan is upcoming |

## Rules

1. **Never bring these up first.** Pitches, openers, follow-ups and drafts use only live features from `02` and `03`.
2. **Only respond if the prospect asks** about one of these needs (for example, "Do you do usability testing?").
3. **Use this wording, adapted to the conversation:**
   > "That's on our roadmap but not available yet. Today Lumor covers surveys end to end: building, recruitment, analysis and reporting. Happy to keep you posted when it's ready."
4. **Then steer back** to a live capability that fits their need, if there is one. For example, a product team asking about usability testing could still run a survey with recruited users today.
5. **Never give:** dates, timelines ("soon", "next quarter", "in a few weeks"), prices, beta access, early-access lists or screenshots. If the prospect asks for any of these, say you'll check with the team and flag it.
6. **Flag every mention.** When a prospect asks about an upcoming feature, raise a flag "Interest in [feature]" so the team can track demand and follow up when it launches.
7. **Never use an upcoming feature to win a deal** ("you'll also get usability testing"). Sell what exists today.
